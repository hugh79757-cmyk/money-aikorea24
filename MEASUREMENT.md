## 1. Funnel-rate table (click → open → result)

```sql
-- Event volume
SELECT event, COUNT(*) AS events
FROM funnel_events
GROUP BY event
ORDER BY events DESC;

-- Distinct users reaching each step (de-duplicated by visitor_id)
SELECT event, COUNT(DISTINCT visitor_id) AS users
FROM funnel_events
GROUP BY event;

-- Step-to-step conversion (share of clickers that opened, and of openers that resulted)
WITH c AS (SELECT COUNT(DISTINCT visitor_id) AS n FROM funnel_events WHERE event='blog_cta_click'),
     o AS (SELECT COUNT(DISTINCT visitor_id) AS n FROM funnel_events WHERE event='persona_open'),
     r AS (SELECT COUNT(DISTINCT visitor_id) AS n FROM funnel_events WHERE event='persona_result')
SELECT
  (SELECT n FROM o) * 1.0 / NULLIF((SELECT n FROM c), 0) AS click_to_open,
  (SELECT n FROM r) * 1.0 / NULLIF((SELECT n FROM o), 0) AS open_to_result,
  (SELECT n FROM r) * 1.0 / NULLIF((SELECT n FROM c), 0) AS click_to_result;
```

## 2. Per-variant CTA comparison (A/B)

Variant is assigned deterministically per post via `md5(service_id) % 2` (pipeline T12).
The `cat`/`persona` columns let us segment; the variant index itself is **not** yet
stored as a column, so segment by `src` token (which encodes `{cat}-{persona}`) and
compare mid-CTA (weak/curiosity) vs end-CTA (strong/action) click rates via GA4
`blog_cta_click` *or* a dedicated `persona_step` probe.

```sql
-- CTA clicks by source segment
SELECT src, COUNT(*) AS clicks
FROM funnel_events
WHERE event='blog_cta_click'
GROUP BY src
ORDER BY clicks DESC;

-- Loop-CTA engagement (result → blog, T19)
SELECT COUNT(*) AS loop_clicks
FROM funnel_events
WHERE event='persona_step' AND step='loop_cta';
```
