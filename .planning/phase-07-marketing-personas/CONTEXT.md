# Context: Phase 7 Marketing Persona Studio

> 2026-08-23 브레인스토밍 세션에서 사용자가 직접 결정한 사항. 이 문서가 요구사항의 단일 출처.

## 확정된 결정 (사용자 답변)

### MKT-01 타깃 사용자: 공개 + 가벼운 게이트
- 일반 방문자에게 공개하는 서비스 페이지 (SEO 노출 의도 포함)
- 단, 최소 장벽 존재 — 기본값 권장: **카카오 로그인 사용자만 LLM 생성 가능** (기존 OAuth/세션 재사용), 미로그인은 페르소나 프로파일 열람까지만 허용
- 대안(사용자가 선택 가능하게 설계에 명시): N회 무료체험 후 로그인 유도

### MKT-02 핵심 플로우: 양방향
1. **product-first**: 제품/서비스 정보 입력 → 그것을 살 법한 페르소나 매칭(지역·연령·성별·소득) → 소비 습관·고민·"제품이 등장하는 다음 장면" 스토리 출력
2. **persona-first**: 지역/성별/연령 선택 → 해당 페르소나 소비 성향·고민·구매 트리거 프로파일 + 마케팅 시나리오 열람
- 두 방향 모두 필수 (구현량 감안 안 함 — 사용자 명시)

### MKT-03 생성 방식: LLM 실시간 생성
- 시나리오/스토리는 요청 시점에 LLM이 생성 (프리생성 정적 JSON 아님)
- 서버사이드(Cloudflare Pages Function)에서 호출 — API 키는 Pages Secret
- 무료 폴백 체인 필요: writer.py(11모델)의 축소판을 JS로 이식. 최소 2~3 모델 폴백 + 빈 응답/프롬프트 릭 검증 게이트

### MKT-04 출력 스키마: "드림 고객 시트" 고정 구조 (2026-08-23 사용자 추가 지시)
LLM이 자유 서술하지 않고 아래 필드를 반드시 채우도록 프롬프트+검증 게이트로 강제한다.
출처: 페르소나 설계 가이드(드림 고객 방법론) — "사람들은 기능이 아니라 지금 해결하고 싶은 고민에 돈을 낸다".

| # | 필드 | 정의 |
|---|---|---|
| F1 | 드림 고객 1인 프로필 | 가상 인물 1명 구체화: 이름·연령·직업·거주지 규모·가족 상황 (persona-stats 통계와 일치해야 함) |
| F2 | 현재 장면 | 지금 이 순간의 구체적 묘사 (시간대·장소·하고 있는 행동 포함, 소설 한 장면처럼) |
| F3 | 검색창 문장 ×3 | 이 사람이 실제로 검색창에 입력할 문장. 카테고리어("정통 사주 분석") 금지, 고민 언어 그대로 |
| F4 | 오퍼 한 줄 | 핵심 고민을 그대로 담은 문장 — 랜딩 헤드카피로 바로 쓸 수 있는 형태 |
| F5 | 결제 직전 두려움 | "이게 돈값을 할까" 수준의 구체적 저항 문장 |
| F6 | 미해결 손해 | 이 고민을 안 풀면 잃는 것 (돈·시간·기회) |
| F7 | 이미 쓴 돈 | 이 고민 때문에 이미 지불한 해결 시도 추정 (무엇에, 대략 금액) |
| F8 | 스토리 4단 프레임 | 현재 장면 → 원하는 변화 → 우리의 역할 → 다음 행동. 각 단계 2~3문장 |
| F9 | 다음 행동 선택지 ×2~3 | 결과를 받은 사람이 실제로 취할 행동 옵션 |

검증 게이트: F1~F9 전부 비어있지 않은지 + F3이 카테고리어가 아닌지(길이·조사 패턴 휴리스틱) 검사. 실패 시 폴백 모델 회전 또는 재생성 1회.

### MKT-05 시각화: 눈으로 보이는 페르소나 (2026-08-23 사용자 추가 지시)
"머릿속이 아니라 눈으로 구체적인 모습을 볼 수 있도록":
- 결과를 HTML/CSS 카드로 렌더링 — 기존 `public/cards/` 페르소나 카드 JPG의 시각 언어 참조 (v1은 서버 이미지 생성 없이 CSS 렌더만)
- F8 스토리는 세로 타임라인(4단 카드 연결)으로 표현 — "변화 포인트"(우리의 역할 단계)가 시각적으로 강조됨
- F3 검색 문장은 검색창 UI 목업 형태로 표시
- 인쇄/복사 가능한 단일 시트 레이아웃 (마케터가 그대로 가져다 쓰게)
